# xemu internals: what must not break, and how to triage

Symbols, not line numbers: re-grep before relying on one. For past failed attempts, see xemu-history. V = `hw/xbox/nv2a/pgraph/vk/`, J = `hw/xbox/mcpx/apu/dsp/interp/dsp56k_jit_arm64.c`.

## Invariants (rule → what breaks → where)

### NV2A Vulkan renderer (all of V runs under `pgraph.lock` on the PFIFO thread, or under icount on the thread of the inline pusher run as well (Threads, below), except `glsl.c`'s init-time glslang warm-up thread, which touches no renderer state, and `draw.c`'s pipeline-cache save thread)
- **The Vulkan driver is chosen once per process and latched** (V`instance.c` `resolve_driver`): `XEMU_VK_DRIVER` (diagnostic, overrides everything; a failure exits 1), else off Apple `volkInitialize()`, else MoltenVK unless `display.vulkan.driver = kosmickrisp` (the opt-in: Auto runs MoltenVK, `try_kk`), and then KosmicKrisp unless `nv2a_vk_kk_ineligible_reason()` (the pin: icount or offscreen; x86_64, no Metal presentation, macOS < 26, no Metal 4 GPU) or a strike for this build (below); KK must pass `kk_accept` (copy-present, every surface and texture format), else MoltenVK by its bundled path in the same process. Code that depends on one driver tests `r->driver_id` / `driver_is_moltenvk`, never the setting (`XEMU_VK_DRIVER` may load either, or a loader in front). The surface-upload fast path leans on MoltenVK's tracked single queue (KK heaps are untracked); the visibility primer covers MoltenVK's per-command-buffer visibility flag; stage-hit accounting holds because MoltenVK caches stages only. All three test `driver_is_moltenvk`; off MoltenVK the driver gets `volkLoadDevice()`, and every Apple driver gets CPU triangle fans (`emulate_triangle_fans`). A driver without `VK_EXT_metal_objects` but with `VK_EXT_external_memory_metal` (KK) presents by copy-present (compositor image copied into an MTLHeap-exported buffer, a linear MTLTexture over it) plus a forwarder thread that signals an xemu-owned MTLSharedEvent per compositor timeline value. Past acceptance a failure can only end the process: route it through `pgraph_vk_fatal_error`, which writes the strike marker (`<base>kosmickrisp-strike.txt`) when the setting chose KK or the start window is open. That window covers a crash too: the resolver writes a pid-tagged start line before the KK attempt (and before MoltenVK after a refusal with the dylib loaded), and only its own process removes it, after 600 flips (`pgraph_vk_driver_flip`), at exit or at renderer teardown; never unlink a live process's start line (a second `kosmickrisp` launch on the same data folder writes its own over it, so the first's crash goes unrecorded: an accepted edge case). Any line for this build, bar a live process's start line, keeps `kosmickrisp` on MoltenVK until a Settings pick removes it (`nv2a_vk_driver_retry`); Auto, `moltenvk` and `XEMU_VK_DRIVER` never read it. → a KK-only failure loops on every launch, a black screen, or one driver's workaround leaking into the other.
- **One queue** (`queueCount = 1`). Apple fast paths (`target_is_active` in `pgraph_vk_upload_surface_data`) assume submission order = execution order. Add no second queue or submit thread; keep the non-Apple `#else` full-finish branches. → in-flight image reuse, corruption/crash. V`instance.c`, V`surface.c`.
- **Deferred eviction**: `invalidate_surface_full(allow_deferred)` parks images in `r->invalid_surfaces`. Reuse and prune skip anything `surface_image_in_recording_cb()`. Destroy only when `evict_submit_seq <= retired_submit_count`, on all platforms (submitted ≠ done). New fence-observation sites advance the watermark; new destroy paths take the same gate. → destroying an in-flight image. V`surface.c` `prune_invalid_surfaces`; V`command.c` `pgraph_vk_wait_slot_fence`.
- **One command buffer per frame, `NUM_FLIGHT_SLOTS = 2`**. `pgraph_vk_init_flight_partitions` splits descriptor sets, staging buffers and the query pool per slot. A new per-slot resource, or a faster consumption rate, needs a runtime submit-and-continue guard: release builds compile `nv2a_vk_assert` out. → overrun into the next slot: corruption or a MoltenVK crash. V`renderer.h`, V`debug.h`.
- **Query guard** at the top of `begin_pre_draw()`, before any setup: `num_queries_in_flight >= queries_per_slot - 1` → `pgraph_vk_finish(QUERIES_FULL)` (the -1 reserves the primer). `alloc_report()` guards with `REPORTS_FULL`. Pools = 4096; `XEMU_MAX_QUERIES` shrinks only the query pool (`=64` exercises `QUERIES_FULL`): the report pool stays ≥ 4096 (`max_reports_in_flight`), and `REPORTS_FULL` has no shrink knob. → a late guard binds `framebuffers[-1]`; no guard crashes AGX in `setVisibilityResultMode`. V`draw.c`, V`reports.c`.
- **Primer query**: `pgraph_vk_begin_command_buffer` issues an empty query (`primer_index`) outside any pass, so MoltenVK's `_needsVisibilityResultMTLBuffer` is set before the first encoder exists. New render-pass paths go after it. Reset the query pool only at CB begin, never inside a pass. → AGX crash when a frame's first pass holds its first zpass draw (scenes that open with a clear hide it). V`draw.c`.
- **`MVK_CONFIG_PREFILL_METAL_COMMAND_BUFFERS=0`**: a second layer on top of the primer; keep both. → prefill=2 corrupts streamed textures (large magenta rects), allows the AGX crash, and is slower.
- **Vertex dirty tracking is page-granular.** A copy into the vertex RAM mirror may skip a finish or a fence wait only when memcmp proves that no byte a draw of that slot reads changes (`read_span_content_differs`: per-slot read spans, up to `VTX_PAGE_SPANS` (4) per page, the attribute ranges `begin_draw` notes once the draw's command buffer is fixed, on every page they read, whether or not the slot's window uploaded it); every GPU reader of the mirror must note its bytes there (today only vertex attribute bindings read it: `update_memory_buffer` in `pgraph_vk_bind_vertex_attributes`; index and inline data go through their own staging buffers). `XEMU_VTX_SPAN_FINISH=0` restores the page-wide finish; `XEMU_VTX_SPAN_REFUTE=1` checks each skip against the draws' bound vertex ranges (want `violations=0`). When unsure, finish. Where a command buffer or pass splits moves a few pixels on AGX (≤2 levels), so a finish-policy change can change screendumps, and sometimes occlusion counts in RAM (deterministic reports, Open). → stale vertices, intermittent garbled geometry. V`vertex.c`.
- **GPU counters count in the method path, never in a renderer** (`pgraph/gpu_counters.c`, QMP `xemu-gpu-counters-*`, `xemu-frame-advance` `gpu-counters`): the pusher loop and the kelvin handlers call `nv2a_gc_*` behind one plain `pg->gc_on` test, which orders nothing, so the counters' state is allocated at PGRAPH init (`nv2a_gc_init`), before the PFIFO thread, and never published later; only `occlusion-samples` comes from report delivery (the common report writer, `pgraph_write_zpass_pixel_cnt_report_at`, and under `XEMU_RENDER_NULL_RAM` V`reports.c` `write_reports_from_queue`). A new draw, clear, report or pushbuffer path (a handler, the inline pusher's fused loop, a squash like BEGIN/DRAW_ARRAYS/END) calls its hook, and the hooks only read guest RAM and PGRAPH state. → null and Vulkan count different work for the same commands, or counting changes RAM.
- **A load must leave PGRAPH as a fresh process's load does** (icount): method state the main `nv2a` section lacks rides in `nv2a/pgraph-methods`; loads without it run `pgraph_reset_unsaved_state`, and every load marks all state dirty (`pgraph_mark_all_state_dirty`). New method state the next draws read goes in that subsection. → repeated loads in one process diverge (stale vertex arrays). `hw/xbox/nv2a/nv2a.c`.
- **Deterministic reports are lazy** (icount): GET_REPORT records the slot and traps its page; the first guest access, flatview or mapped DMA to the slot, a pause, savevm/sync_ram, RESTORE_VM, slot reclaim and the full-pool or flush drains deliver. The APU's direct `ram_ptr` accesses are not trapped. A new renderer path that reads or writes guest VRAM calls `pgraph_vk_det_reports_guard`; a new vCPU-thread reader that copies RAM directly calls `nv2a_det_reports_sync_read` on those bytes first, holding no lock but the BQL (it waits for PFIFO, BQL dropped), as `xemu_hook_read`, frame-advance trace samples and value stops do; no global eager mode (delivering at every park made each of Azurik's visibility tests a finish: 76-80 a flip in d2 while a hook read memory); after a load, `flush_discard` drops what is left. → a hook or trace reads a stale slot. Open: where a command buffer or render pass splits changes later report sums (stream-e2 + input: an old eagerly traced replay differed by one occlusion count from frame 56; dropping MoltenVK's per-fan pass restarts (CPU fans) moves standing stream-e2's by 1-4 from frame 60) and pixels (eager vs lazy screendumps: 108 pixels on heavy-f1, 52 in d2), so `XEMU_TRACE_RECORD` reads RAM as it is (`XemuHookCtx.raw`). Also open, offscreen only: a checkpoint's restores agree with each other, but not with the run that went on from the save, and neither matches a run that never saved (heavy-f1 f300 + 120: `6c1acd31…` unsaved, also after a second loadvm; `9fadc98a…` went on; `94a9e910…` every restore, incremental or full; base c3327bc088 the same; null agrees everywhere). The save writes surfaces back and finishes (`nv2a_save_quiesce`), the restore drops renderer state; which of those moves RAM is unmeasured. V`reports.c`.
- **Pipeline-cache saves run on their own thread** (`pgraph_vk_maybe_save_pipeline_cache`, at flips: 16 new entries or a load's burst settled, 1 s after the last miss, ≥5 s apart, else 30 s): it only calls `vkGetPipelineCacheData` and writes `<base>pipeline_cache.bin.<pid>.tmp` (KosmicKrisp: `pipeline_cache-kosmickrisp.bin`, one file per driver) then renames. Keep the VkPipelineCache internally synchronized (never `VK_PIPELINE_CACHE_CREATE_EXTERNALLY_SYNCHRONIZED_BIT`) and the saver at the PFIFO thread's QoS (a creation waits on its serialization), join the thread before `vkDestroyPipelineCache`, and count only creation-feedback misses (`pgraph_vk_pipeline_cache_note_created`: a pipeline hit, or on MoltenVK, which caches stages only, every stage a hit, is not new; every creation through `vk_pipeline_cache`, draw, clear, display and surface compute, reports there, or its misses never get saved on an otherwise warm run), so warm runs never write and never clobber a sibling's fuller cache. Concurrent instances can still lose each other's new entries (last rename wins), never tear the file. → use-after-destroy at exit, torn cache, or det runs paying for saves. V`draw.c`.
- **Frame pipelines share one dynamic-state list, set only through `r->dyn`** (`r->frame_dynamic_states`: viewport, scissor, blend constants, depth bias, and line width with `wideLines`). Every graphics pipeline bound into `r->command_buffer` declares it (`create_pipeline`, `create_clear_pipeline`; the compositor records its own command buffers, surface compute binds compute only). gpuprops records `r->command_buffer` with its own pipelines once at init, before the first `pgraph_vk_begin_command_buffer` (which resets `r->dyn`); anything else that records into `r->command_buffer` binds only pipelines that declare the list, or resets `r->dyn`. Every `vkCmdSet*` in V`draw.c` goes through the `dyn_set_*` helpers, the partial clear's scissor and blend constants included, and the shadow resets only in `pgraph_vk_begin_command_buffer`: binds, render-pass restarts and `vkCmdClearAttachments` keep it, and a command buffer's first draw sets every listed state. `blendConstants` stay zero in create info (KosmicKrisp keys pipelines on them). → Mesa drivers (KosmicKrisp, RADV, ANV, lavapipe) copy a bound pipeline's static state into the command buffer, the shadow then skips the set that would restore it, and draws run with depth bias 0, blend constants 0 or line width 1.0; MoltenVK keeps static and dynamic values apart and hides it. V`draw.c`.
- **`XEMU_RENDER_NULL_RAM` keeps guest RAM the null renderer's** (V`renderer.c` `null_ram_setup`, opt-in; `1` and `request` both replace the op table with the `null_ram_*` wrappers, runs without it keep the plain table): reports are written 0 at GET_REPORT (`null_ram_get_report`), and the queried count goes only to `occlusion-samples` (V`reports.c` `write_reports_from_queue`'s `null_ram` branch, the GPU counters' second report-delivery site), `download_surface` writes nothing, blits don't run; `request` also skips draws, dropping renderer state (`null_ram_drop_state`) when skipping starts and when drawing resumes at a flip, and a skipped flip still runs the flip's housekeeping (`pgraph_vk_driver_flip` for the KosmicKrisp start window, the pipeline-cache save check, `nsprof_flip_tick`). A new V path that writes guest RAM checks `r->null_ram`; a new per-flip duty in `pgraph_vk_flip_stall` that isn't drawing goes in `null_ram_flip_stall`'s skipped branch too. → that mode's RAM digests part from null's, or a skipping run leaves the KK start window open (a later crash becomes a strike).
- **A draw pipeline is built from its key only.** `create_pipeline` takes rasterizer, depth-stencil and blend state from `key.raster` (`RasterState`, filled by `pgraph_vk_get_raster_state` from BLEND, CONTROL_0-2 and SETUPRASTER, every field an off enable ignores zeroed), never from the registers; new register-derived pipeline state goes into `RasterState` there. `check_pipeline_dirty` still tests the raw registers, so a write that leaves `RasterState` equal is a keyed hit on the bound pipeline. → two register states that differ in an unkeyed field share whichever pipeline was built first. V`draw.c`.
- **Surface expiry** throttles on monotonic time (`surface_expire_interval_ns` 33 ms), never on `pg->frame_time`. → black-screen freeze on rapid level loads. V`surface.c`. Exception, icount only: expiry runs once per flip or every 4096 updates, reports are delivered before PFIFO rests, and a load discards renderer state (`flush_discard`), so offscreen Vulkan is deterministic.
- **The vsh fog carryover runs a slice of the program** (`pgraph/vertex.c`, after every Vulkan and GL draw, never in the null renderer): `vsh_carry_build_slice` keeps the steps that can reach the final oFog by register liveness, so an nv2a_vsh_cpu bump that changes which registers a step reads or writes (temporary 12 reads oPos, the oFog writemask rule, new output kinds) must be mirrored in `vsh_carry_out_reg`/`vsh_carry_in_regs`; slices are keyed by the program words through the final step. A carried-fog change marks no uniforms dirty only because every oFog write sets oFog.x in the generated GLSL (`fog_mask_str`), so the program that changed it never reads `vshCarryFog`; a load marks them (`nv2a_post_load`). → a fog value that drifts from upstream's, or a stale `vshCarryFog` behind the uniform skip-gate.

### DSP56300 JIT / APU
- **Engine precedence** lives only in `dsp_want_external_jit_engine()`: `DSP56K_JIT_SUPPORTED` (aarch64, non-Windows) + `audio.dsp_jit.enabled` (default true) → fork JIT inside the C interpreter (`c_dsp_ops`); else `audio.use_dsp_jit` → upstream `jit_dsp_ops`; else the plain interpreter. Keep the `dsp56k_jit_*` (fork) and `dsp_jit_*` (upstream) namespaces apart. `use_dsp_jit: true` is a fork default: re-assert it after upstream merges. The inline JIT runs both cores. → wrong engine live; diagnostics measure the wrong one. `dsp/dsp.c`, `config_spec.yml`.
- **JIT blocks are keyed by start PC and may overlap** (entering mid-block builds a second block). A block depends on `[pc_start, dep_end)`: its op words, the second word of a two-word last op that `dsp56k_jit_helper_inst_length` calls one word (DO, BRA long, mode-6 ea), and every word the lazy-flag lookahead read past the last op (`xlate_peek_p`); movem p:aa bakes go in `bake_mask`. A P write inside either evicts it (`cover[]` keeps a data write O(1)). A new translate-time P read goes through `xlate_peek_p`, or stays inside the op's words or `bake_mask`; going back to one owner block per PC brings back the EP churn (two blocks at a shared PC rebuilding each other). → stale code runs after a P write. J `dsp56k_jit_invalidate`.
- **Lazy flags**: the lookahead drops an op's E/U/N/Z update (or one half) when a later op in program order overwrites it before any read. A DO-loop edge inside that window runs SSH instead, so every dropped update keeps `emit_ccr_edge_guard` (computes it when LA lies between the op and its killer). A walked-over passthrough reads no E/U/N/Z and writes no LA; check a new writer or passthrough against the interpreter (ENDDO keeps the CCR; Tcc NN/EC/NR/ES read E/U). → stale flags at a branch/Tcc; the `lazy-flags` corpus program. J `lazy_flag_lookahead`.
- `dsp->core` is only the save/restore snapshot (`dsp_sync_to_vm`/`_from_vm`); live state is `dsp->backend`.
- **W^X**: every code-buffer write, including `chain_repatch_b` patches into other blocks, happens inside `qemu_thread_jit_write()` → writes → `jit_clear_icache` → `qemu_thread_jit_execute()`, in one function. No TLS-cached W^X state, no `pthread_jit_write_with_callback_np`. → SIGSEGV now, or SIGSEGV/SIGILL about a minute in. J.
- **Pins**: A/B in x26/x27, packed X/Y in x20/x21, SR low 16 bits in x28. `dsp->registers[]` stays authoritative: write through, and reload pins (`emit_reload_*_pins`, `emit_reload_sr_pin`) after any BLR fallback that may touch them. Verify with `XEMU_DSP_JIT_PIN_AUDIT=1`. → silent audio corruption on rare paths. J.
- No block boundary may skip `dsp_postexecute_update_pc`, which decides REP/DO continuation. The JIT epilogue inlines all but REP and the loop edge (`dsp_do_loop_edge`, shared with the interpreter) and tests `loop_rep` only on a block's first op, on an op whose body may set it, and on the op after, so anything new that sets `loop_rep` after Step 5 must exit the block itself. → PC desync.
- **The per-op epilogue trusts the emitters' bookkeeping** (`emit_post_instruction_epilogue`). One LDR X of the exit word (`jit_exit_word` = `interrupt_state`, `interrupt_counter`, `interrupt_pipeline_count`, `is_idle`, `jit_exit_block_request`) replaces the interrupt/idle/exit-request loads; a new exit flag goes inside it. An op whose body stores neither `pc` nor `cur_inst_len` (`note_store`: STR/STRH/STRB on x19) and calls only `blr_effects`-whitelisted helpers stores pc from a constant and skips the main-line PC check; the check stays on every path that can move pc (REP helper, loop edge, interrupt helper). Write those fields only through the store primitives on x19, and whitelist a helper only after reading everything it can reach. → PC desync, or an exit taken one op late. J.
- **Chain sites** (J `translate_block`, `jit_static_succ`, `emit_cold_stubs`, `chain_route`): a block-ending op's static successors (taken target, conditional or DO/ENDDO fall-through) and the translate-time loop's rewind at its LA end in B sites. Each sits behind the op's exit-word test and a pc compare against its target's start, and is registered in the target's `incoming_chains` (or `pending_chains` until the target exists) so eviction unpatches it. A new site keeps all three; no site to the block's own start except a loop rewind (LC bounds it). `XEMU_DSP_JIT_DIFF` turns chaining off, so only the goldens, `XEMU_AUDIO_WAV`, `XEMU_DSP_JIT_PIN_AUDIT` and the xbox suite's `corpus-jit` and `jit-differential` arms check chained paths. Every block's chain entry leaves, before its first op, once `num_inst` has reached `jit_chain_limit` (`dsp56k_jit_execute_block` sets it from `dsp_run`'s budget), so a chained run stops at the block boundary where dispatching one block at a time would; a new way into a block from JIT code goes through `chain_entry`. The auto-throttle counts a chained run as one dispatcher entry. → stale or skipped code after a P write; an exit taken late; a polling loop of two chained blocks that never returns to `dsp_c_run` (the APU frame thread spins holding `d->lock`), or runs that depend on which sites are patched.
- **A bulk P change revalidates, it doesn't flush** (`dsp56k_jit_revalidate_all`: DSP reset, bootstrap, opcode-cache flush, `sync_from_vm` on a load). The next `dsp56k_jit_execute_block` compares every live block's dependency words (`dep_words`: its `[pc_start, dep_end)` and `bake_mask` words as translated) with P memory and evicts the blocks that differ before any block runs, so chains only ever join verified blocks. Kept blocks and chains must not change results: a restore runs exactly as a fresh pass from the same state did, because a chained run stops at `dsp_run`'s budget (`jit_chain_limit`) and a translation depends only on its P words (a translate-time DO loop adds only a pc-guarded rewind site); xbox suite `/corpus/budget-replay`. A new bulk writer of `pram` calls it; a per-word P write keeps `dsp56k_jit_invalidate`; `dsp56k_jit_invalidate_all` is only for a full code buffer. → stale code after a load or a program reload.
- Voice registers live in guest RAM; the `voice_buf` cache must fall through to `ram_ldl`. → stale voices. `apu/vp/vp.c`.

### Present path
- **Push ring is the default** (`pgraph_vk_push_present_enabled`: Metal backend, metal-objects extension, not headless). `pgraph_vk_present_schedule_publish` publishes at flip; `nv2a_get_present_frame_pushed` consumes. Leaf mutex (`present_slot_lock`), a CFRetain per entry, a generation counter: never lock-free. The cursor only moves forward. → use-after-free of IOSurface handles; frames out of order. V`display.c`.
- **Pull fallback** (GL, headless, before the first publish, after a resize): `nv2a_get_present_frame` → `pgraph_vk_get_present_frame` (`sync_pending` + `pfifo_kick` + `qemu_event_wait`). One consumer (`framebuffer_in_use` assert). Keep both paths correct; add no synchronous work to the `sync_pending` handler. → UI latency on every frame. `pgraph/pgraph.c`, `ui/xemu.c` `metal_render_frame`.
- **`encodeWaitForEvent` comes before the drawable render pass** opens. → a frame the GPU hasn't finished gets presented. `ui/xemu-metal.m` `xemu_metal_begin_frame`.
- **A readback of a present frame waits for its event too** (`NV2APresentFrame.event`/`event_value`, passed to `xemu_hud_save_frame`): the compositor submits asynchronously on the Vulkan queue, behind the frame's own command buffer, and headless composites only for a screendump. → the readback runs first and writes the previous screendump's picture (from before a load, a level change, or the last flip). The F12 screenshot and savestate thumbnails get the pair with the texture (`xemu_hud_set_framebuffer_texture`, `xemu_snapshots_set_framebuffer_texture`; NULL/0 for a VGA upload). `ui/xemu.c` `screendump_service`, `ui/xui/metal-helpers.mm`.
- **Headless null mode scans VGA only on demand**: `nv2a_vga_gfx_update` skips `vga_update_display` (the VBLANK IRQ and raster reset still run), so the console surface stays stale until `nv2a_vga_refresh()` (BQL held; a full redraw that clears no dirty bits). A new null-mode reader of `scon->surface` calls it first, as `screendump_vga` does in every mode (no vblank has scanned yet after a load or at launch). → stale or wrong-sized frames. `nv2a/nv2a.c`.
- **Vblank**: `vblank_timer_thread` ticks every `vblank_interval_ns = 16666666` on monotonic deadlines and raises the guest VBLANK interrupt; never tie it to host refresh. No PAL 50 Hz path exists. → guest simulation retimed. `ui/xemu.c`.
- **Launch parity**: every `Info.plist` `LSEnvironment` variable is mirrored in `main()` with `setenv(...,0)` before MoltenVK loads (six MVK keys), whatever `display.vulkan.driver` says (MoltenVK may load as a fallback after a KK attempt; KK ignores them). A variable exported in the shell overrides both. → Finder and terminal launches run different configs. `ui/xemu.c`, `Info.plist`.
- **AppKit window restoration stays off** (`ApplePersistenceIgnoreState`, registered by a constructor before `main()`): SDL3 registers it only after AppKit's launch-time check, so after a crash of any app named xemu the next windowed or offscreen launch runs a hidden "reopen windows?" alert on the main thread. → screendump and `quit` stall until someone answers (null mode starts no Cocoa app). `ui/xemu-os-utils-macos.m`.
- **No GL context is current on the UI thread under the Metal backend** (`xemu_present_is_metal()`, latched for the process; leaving Vulkan in Settings waits for a restart, so the renderer setting can read OpenGL or Null while Metal presents): every UI reader of GL strings or state checks it first and reports the Metal device instead (`compat.cc`, the About box, `github-issue.cc`, the startup log). Upstream merges add readers without the check. → `glGetString` with no current context: SIGSEGV. `ui/xui/`.

### Deterministic mode (`-icount ... sleep=off`, null renderer)
- **Guest state changes only at fixed instruction counts.** No device thread may touch guest RAM, registers or IRQs on its own schedule: PFIFO pushes inline on the vCPU (`pfifo_icount_sync`; the GL renderer's pusher stays on its thread, which the vCPU waits for), APU frames run in `mcpx_apu_det_tick` (virtual timer, BQL held, default FPCR), IDE drains before the guest access returns (`ide_bus_icount_settle`; on file-posix hosts, macOS and Linux, and through file-win32's coroutine reads and writes on Windows, the host I/O itself runs inline on the vCPU, `thread_pool_set_inline`, so a vCPU-side block request the guest doesn't wait for has no place here; the settle's bottom halves don't wake the main loop, `aio_bh_notify_defer_begin` and `aio_wait_self_waiters`, since a main-loop wakeup per request cost a third of the cold boot), pads change only at vblank ticks. A new device thread or async completion breaks bit-exact replays. → RAM differs between identical runs.
- **A stopped VM runs no virtual timers** (icount): only `vm_start` enables `QEMU_CLOCK_VIRTUAL`, and the rr vCPU loop leaves it alone while the vCPU can't run. A load moves the clock to the save's, so timers outside vmstate (vblank, the APU tick: both rearmed at the next start) and overdue restored ones (OHCI, PIT) are due at once; they must run on the vCPU after the start, never in the paused VM (check: `XEMU_LOAD_VERIFY=1`). → a paused load starts on other RAM, about 1 in 70 harness loads. `accel/tcg/tcg-accel-ops-rr.c`.
- **A save between a load and the next start records no APU tick deadline** (`mcpx_apu_history_pre_save` while `det.rearm`): the timer may still hold the previous session's, and the start puts it on the grid, so the restore must too. → a checkpoint taken right after a paused loadvm, in a process that ran before, continues differently from that loadvm. `hw/xbox/mcpx/apu/apu.c`.
- **Host state not in the savestate is reset on load** under icount (APU resamplers/HRTF/`ep_frame_div`, DSP JIT throttle, AC'97, the PM GPIO field pin). Per-read toggles and static counters in read handlers are the usual culprit. → runs alternate A/B/A/B.
- **Loads keep the translation cache** (both modes): `qemu_loadvm_state` calls `xemu_tb_revalidate_after_load`, which keeps a TB only while its guest bytes still hash to `tb->ihash`, re-protects every page that keeps code, and resets the jump caches (and with them the step TB cache), RAS, cross-page chains (`tlb_flush`), the icount step and the xpage refuter shadows; a failed load still flushes. After an incremental checkpoint restore the check is scoped (`xemu_tb_revalidate_pages`): it hashes and re-protects only the pages `xemu_checkpoint_ram_reval_scope` names, those the restore wrote plus every page the migration dirty log saw written since the last check (`Block.reval`: saves don't clear it; valid only while the log ran since then, `reval_ok`), so a writer that changes RAM and neither marks the log nor invalidates (or sets DIRTY_MEMORY_CODE without marking the log) leaves a stale TB; loadvm, incoming migrations and full restores keep the full walk. Refute with `XEMU_TB_REVAL_REFUTE=1` (`extra drops 0, unprotected pages 0`). A TB may depend only on its bytes `[pc, pc+size)` and lookup key: a translator that reads code past its end sets `XEMU_TB_PEEKS` (never recycled, dropped at every load from its own list, `xemu_peeks`; `gen_STI`'s idle match), new translate-time global state flushes when it changes, and host state keyed on `tb_flush_count` is reset there too. → stale code after a load; repeated loads in one process diverge from fresh ones. `accel/tcg/tb-maint.c`, `ui/xemu-checkpoint-ram.c`.
- **Guest PC hooks** (`target/i386/tcg/xemu-hooks.h`, `xemu-run-until`): a hook site always starts its TB, whose first op calls `helper_xemu_hook` (not in a one-instruction CF_NOIRQ TB: cpu_io_recompile, precise SMC and watchpoints use one to re-execute an instruction that already started, whose hooks already ran); code elsewhere translates unchanged, so every TB entry path runs the hook and no fast path needs a hook check. A CF_PCREL TB runs at every mapping of its code, so the translator also starts a TB with the call at each RAM address a site's PC has mapped to (`XemuHookTable.phys`, from the pages `sites_cover` recorded; publish after covering), and the call reads the running PC, so at an alias it finds no site. A site's TBs are dropped past the recycler (`xemu_tb_invalidate_page_norecycle`) on each page its PC maps to, because the bytes don't change; a new TB cache layer must not revive a TB translated before a site existed. A hook changes guest state only through `xemu_hook_write` (RAM through the memory API, as a gdbstub write: TBs invalidated, dirty bits, nv2a callbacks; a write on a page of its own TB, which page-wide invalidation drops whatever bytes the write covers, makes the engine leave the TB and re-execute the instruction from fresh code, since a TB invalidated before its jump target keeps its direct jump into the old code), and stops only through `xemu_hooks_stop`/`_stop_rerun` (EIP restored to the site, none of the TB run); on resume the engine skips, for that re-executed arrival, the hooks that already ran for it (`hook_resume`, by priority and id), calling the stopper again only for `_stop_rerun` (a set hook's held write lands then, at the same instruction), and a load drops the resume (`xemu_hooks_state_loaded`). Hooks run without the BQL: `xemu_hooks_stop` takes it, so never call it holding another lock (the collect records' `rec_lock`). `xemu-hooks-drain` takes the records while the VM runs (under `rec_lock`) and relies on QMP running one command at a time to never cut into an advance's records or stop: keep it out of OOB. `xemu-run`'s value stops only read RAM, at vblanks (`xemu_frame_advance_set_vblank_stop`, before the trace sample; in normal mode the vCPU thread asks them between blocks right after the vblank, `frame_vblank_stop_on_cpu`), and end the advance by moving its target to that vblank, so a stopped run is a plain advance to that frame; its restore runs in an iohandler BH, never in the QMP coroutine. Code outside a hook (value stops, `XEMU_TRACE_RECORD` expression regions) reads an expression through `xemu_hook_expr_read_cpu0` (`exec/xemu-hook-expr.h`) with the BQL held and no guest instruction running (an icount vblank, or the vCPU thread between blocks), never from another thread while the vCPU runs: TB code keeps CPU 0's GPRs and EIP in host registers (see the pinned-register rule); it calls `xemu_hooks_init`, which caches `xbox.ram` once, so nothing may call either before the machine exists. `helper_xemu_hook` keeps no call flags: it reads the GPRs and EFLAGS and may restore EIP and leave by `cpu_loop_exit`, so every pinned home must be stored before it and reloaded after (see the pinned-register rule). → hooks miss or repeat arrivals, a write lands at another instruction, a stop/resume moves RAM, or a deadlock. `target/i386/tcg/system/xemu-hooks.c`, `xemu-hooks-qmp.c`.
- **gdb breakpoints are hook sites** (both modes; `xemu_gdb_bp_site_insert`): each BP_GDB PC gets a `XEMU_HOOK_PRIO_GDB` hook that runs before any other at the site and leaves by EXCP_DEBUG after `cpu_restore_state` (EIP at the site, none of the TB run, no `hook_resume`, so a later arrival is never skipped), stepping aside while `singlestep_enabled` (`s`, and the Qxemu.stepover step, which runs single-stepped). `check_for_breakpoints_slow` keeps the exact-PC check at lookups and sets CF_BP_PAGE only for DR7 (BP_CPU) breakpoints; fast paths that enter TBs without a lookup (the ret memo, the icount step cut, new cross-page links) step aside only for BP_CPU (`xemu_cpu_breakpoints`). Only a PC's first breakpoint covers its page (norecycle; safe work when inserted while the VM runs); z0 leaves the hookless site. Like every site, it also cuts TBs translated at another mapping of its code (see the hooks rule), since a CF_PCREL TB found by physical address may run at the breakpoint's PC; the old CF_BP_PAGE cflags kept such TBs apart. → missed or repeated breakpoint hits, or 30% slower frames while one is armed. `target/i386/tcg/system/xemu-hooks.c`, `accel/tcg/cpu-exec.c`.
- **Step TBs are cached by virtual pc** (`xemu_step_lookup`), so the step cache must drop a page whenever the jump cache does: `tb_jmp_cache_clear_page` and `tcg_flush_jmp_cache` stamp it. A new way to clear the jump cache, or to change a code mapping without a TLB flush, stamps it too; TB invalidation needs nothing (`CF_INVALID` misses). Only the vCPU thread touches it. → a step runs a TB from an old mapping. `accel/tcg/cpu-exec.c`.
- **A reload of the same CR3 keeps what the page tables still map** (both modes; `xemu_write_cr3` → `xemu_tlb_reval`; the kernel's only TLB flush, 509 per 600 det stream-e2 frames). Every TLB fill that walks the page tables logs the words it used (`xemu_tlb_log_fill`: the 32-bit walk's PDE and PTE by host pointer, as its A/D update left them, by virtual page, with the mmu_idx), so the log covers every page filled since the last full flush, which alone resets it (`xemu_i386_tlb_log_reset` in `tlb_flush_by_mmuidx`). A fill it can't record (PAE, NPT, a table outside RAM) or a 65th page table loses the log, and the next reload flushes everything; so does a changed PDE, or more than 1024 changed pages (cheaper as a full flush). Otherwise a reload flushes only the logged pages whose PTE changed or was refilled from other bits than A/D (`tlb_flush_page_by_mmuidx`, which drops their jump-cache, step-cache and ret-memo entries) and severs the cross-page chains only when such a page's old frame held TBs (`xemu_tb_page_has_tbs`, under the page lock: a TB another thread is invalidating keeps its incoming jumps until then): an unchanged page is not a mapping change for the step cache, ret memo or xpage rules. A new TLB fill path logs or loses the log; new state derived from a virtual mapping is made after a fill of its page and dropped with the page's jump cache. Refute with `XEMU_TLB_REVAL_REFUTE=1`: it aborts on a kept TLB entry, jump-cache, step-cache or memo TB that maps other memory than a fresh walk or sits on a page the log misses, or a chain into a dropped frame; the `tlb-reval` exit line counts its checks (also printed under `XEMU_TB_PROF`). → stale code or data after the guest remaps a page; RAM diverges from the goldens. `target/i386/tcg/system/excp_helper.c`.
- **`tb_gen_code` may flush the whole cache and return a new TB** (serial context, which the Xbox's single vCPU always is: a full buffer runs `tb_flush__exclusive_or_serial` in place), so a caller that holds a TB across it compares `tb_flush_count` first (`cpu_exec_loop` drops `last_tb`). → a link patched into reused code: SIGSEGV in the xpage unlink or a jump into another TB. `accel/tcg/cpu-exec.c`.
- **Run device work on the vCPU thread under the default FPCR** (`xbox_host_fp_enter`/`_leave`, `hw/xbox/host_fp.h`): TCG leaves the guest x87 RC in the host FPCR and reprograms it lazily. On aarch64 the bracket writes FPCR only when it differs and leaves FPSR alone, as nothing reads it; code that starts reading host exception flags must clear them first. → float results depend on history.
- **Inline SSE arithmetic trusts the host FPCR** (both modes): addps/subps/mulps/divps compile to FADD/FSUB/FMUL/FDIV .4S (`gen_fp_sse_inline`) only in TBs whose flags carry `HF_SSE_DFL` (hflags bit 2: MXCSR RC nearest, FZ and DAZ clear) and x87 RC nearest. FPCR follows the x87 RC, not MXCSR: `update_fp_status` sets the calling thread's, and `x86_cpu_exec_enter` re-applies it on the vCPU thread at every `cpu_exec` entry (reset, gdbstub and loadvm write FCW from the main thread). FZ is set only inside the SSE helpers' bracket, so vCPU-thread code that changes FPCR puts it back before guest code runs. The x87 write-through memory operands rely on that FPCR as well: m32fp widens with FCVT and m64fp quiets a signalling NaN with FMAX (`quiet_f64`), both exact only under FPCR.DN = FZ = 0 (and AH = 0). MXCSR changes only through `update_mxcsr_status`, which keeps the flag (only while `xemu_sse_vfp` is on); a TCG writer ends its TB with `DISAS_EOB_NEXT` (LDMXCSR, FXRSTOR, XRSTOR), never the `DISAS_JUMP` probe, which reuses the TB's flags. x86_64 hosts: the host MXCSR flags hold `sse_status`'s while an SSE helper's host op runs, and `xemu_hostfp_leave_lazy` ORs them back. → SSE math rounds or flushes under a stale mode; x87 memory operands flush or lose their NaN payloads. `target/i386/tcg/emit.c.inc`.
- **Deferred x87 FIP/FCS and stores land at mid-TB exits from insn_start word 2** (both modes): `i386_tr_insn_start` puts the distance back to the insn whose FIP/FCS update is pending in bits 0-11, and the insn's first guest access adds the write-through results still waiting for their st80f in bits 12-19 (shadow slot r = register (fpstt + r) & 7, fpstt as the flush interval found it), and the stack bookkeeping still deferred at the insn's start: bits 23-25 how far fpstt moves, bits 26-33 and 34-41 which tag bytes land and their values, by the same slots. Write-through blocks, and on x86_64 every block with the host x87 ops (hard FPU, `g_x87_hw`) (`x87_defer`), defer fpstt and fptags (`x87_wt_land`): push, pop, ffree, fdecstp and fincstp only move `fpstt_delta` and note tags, and env catches up at the next flush, so env->fpstt is the interval's at every exit (the `fpstt` global is unused there; read the current top through `gen_st_index`). Bits 20-22 `top`, the shadows' offset from env->fpstt, are 0 except after a flush that followed the insn's first access: that flush moves a landing of the insn's starting stack state to just before the access and clears bits 23-41 (`x87_wt_land_early`), since fpstt must not move twice, which leaves `top` = `-delta & 7`. `x86_restore_state_to_opc` → `xemu_x87_restore` lands the FIP, then the stores and tags at (fpstt + top + r) & 7, then moves fpstt. Under icount, those blocks defer FDP too: it is a runtime value, so every guest access while one is pending stores it on its slow path (`xemu_x87_defer_fdp`; `gen_ldst_prologue` emits `tcg_gen_st_i32_slow` last, right before the access) and the flush stores it in line; other blocks store it per insn. The held FDP is the insn's own address temp when it has 32-bit addressing, no override and no segment base (`own_a0` in `gen_x87`), which also addresses its access, so no x87 code may write `s->A0` after the lea (an access at an offset takes its own temp); the refuter compares the hold at every flush. FDS is deferred with it (`xemu_x87_defer_fds`): the flush stores the selector of the pending insn's segment, and a mid-TB exit lands it from word 2 bits 43-45 (segment + 1), which works because a selector changes only inside a helper, after its call-site flush, or in `gen_op_movl_seg_real`, which flushes first; other blocks store FDS on segment change (`xemu_fds_seg`). Keep word 2 to those fields (bit 42 is the refuter's FDP mark); a new inline write of `segs[].selector` or `fpds` must call `xemu_x87_flush_ptrs` and reset `xemu_fds_seg` first, as `gen_op_movl_seg_real` does. Refute with `XEMU_X87_REFUTE=1`: every `*violations=` field must be 0. → FNSTENV/FNSAVE see a stale FIP/FDS, or the x87 registers lose results, after a guest fault or MMIO exit. `target/i386/tcg/xemu-x87.h`.
- **A write-through x87 result reaches env only at the next flush** (both modes; `gen_flush_fp`: every helper call except the argument-only `cc_compute_all`/`cc_compute_c` (`gen_pure_call_begin`), every BB_END op and the TB end; as its double with a static TOP, see the next-but-one rule), so a slot written again first stores once (`x87_wt_pend`). Until then its env image is stale: TCG code that reads or writes an image directly (register copies, fxch, fchs/fabs, fld1/fldz, FT0 for a helper) goes through the cached double or `x87_wt_sync`; C code runs only behind a call, which flushes unless it reads nothing but its arguments. fucom* and the fcmov select (`movcond_f64`, FCSEL on the prepared condition) run on the doubles only for slots whose image is st80f of the cached double (`wt_exact`): one read back with ld80f may hold more than a double, which the helpers' 80-bit compare sees. Every mid-TB exit must pass `restore_state_to_opc`, which converts the shadows. Only a guest access's slow path stores them (`gen_ldst_prologue` → `x87_wt_spill` emits `st_f64_slow`, which must come right before its qemu_ld/st; the aarch64 and tcg/i386 slow paths perform it, and the value's register, integer or FP, stays reserved until the access is emitted (on tcg/i386 it is first moved out of L0/L1, which the TLB lookup writes before its branch, and EAX, `x87_cmp_g`'s output: `TCG_TARGET_SLOW_ST_AVOID`) (`slow_st_held`: the access may allocate registers before its slow-path branch, V registers too for the m32fp/m64fp operands' `qemu_ld_fp`/`qemu_st_fp`; a pinned global's home already is, and stays so), and the stub's store prefilter, which runs before those stores, takes its scratch from x0-x3 outside them), so any other new way to leave a TB mid-block needs its own spill. A flush inside an insn freezes its word 2; if an access came first, the flush also stores the shadows in line, and no helper reached after an access in the same insn may write x87 registers. An insn's own push, pop and tag changes may not reach env before its last guest access (a restore does not roll them back; `x87_wt_land_early` lands only the state deferred from earlier insns). No hatch (det-verifiable TCG change, owner rule): suspect it with `XEMU_X87_REFUTE=1`. → registers silently keep an older value. `target/i386/tcg/translate.c`.
- **TBs are keyed on the x87 TOP** (both modes, hosts with the write-through path or the host x87 ops (x86_64, `g_x87_hw`: fixed env offsets in every block): `xemu_x87_top_key`): `x86_get_tb_cpu_state` puts `env->fpstt` in `cs_base` bits 32-34, deferring blocks (`x87_defer`) address ST(i) and the tags as fixed env offsets from `x87_top`, and goto_tb, the jump-cache probe and the ret memo pass the exit's TOP as a constant (`x87_key_cs_base`). A helper that moves fpstt needs `x87_top_move`/`x87_top_set` right after its call (never before: the call's flush lands the old TOP); one that moves it by a runtime amount sets -1 (fptan, fsincos, the restores), after which addresses come from env and exits take `helper_lookup_tb_ptr`. Whoever reads `tb->cs_base` as a segment base truncates it to 32 bits, and the icount step resume compares only that half (a step may push); every TB cache compares the whole key (both jump-cache ways, the step TB cache `xemu_step_lookup`, the ret memo). Refute with `XEMU_X87_REFUTE=1` (`top-key-violations=0`). → a chained or probed TB built for another TOP: the x87 registers silently shift. `target/i386/tcg/translate.c`.
- **x87 registers live as doubles between blocks** (both modes, write-through blocks with a static TOP: `x87_wt_dbl`): a flush stores a pending result's double to `env->xemu_x87_dbl[p]` and sets `env->xemu_x87_dstale[p]` instead of converting it, so `env->fpregs[p]` is stale until something converts it, and a TB read takes the double while the byte is set (`ld80d`). Every C reader or writer of `env->fpregs` goes through `x87_reg` (fpu_helper.c `ST`/`FPR`) or calls `xemu_x87_sync` first (the fsave tag scan, the gdbstub, `cpu_pre_save`, and `helper_enter_mmx_sync`, since MMX code moves images raw: the TB's first full MMX entry (`gen_enter_mmx`, or the first after a flush stored a double: `mmx_synced`, decided after the entry's own flush) calls it whenever env's eight stale bytes are not all clear, and the inline entry must keep that test); `cpu_post_load` and XRSTOR's init drop the bytes (`xemu_x87_drop`); code beside a running vCPU reads `xemu_x87_reg_value`. TCG code that moves an image raw moves the double and the byte with it (`x87_wt_copy_dbl`); FT0 for a helper goes through `helper_fmov_FT0_STN`; a mid-block restore clears the bytes it lands. Precision control single (`update_fp_status`) and every helper after which the TOP is unknown (fptan, fsincos, fldenv and the restores, `x87_top_set`) sync, so blocks that run lean ops on raw images never see a byte set. What the translator knows about the bytes (`wt_nstale`) dies at every flush (a label may be reached by a branch). A helper that reads an x87 register may write env, so never give one `TCG_CALL_NO_SIDE_EFFECTS`. Refute with `XEMU_X87_REFUTE=1`: the poison stays exactly on pending or stale registers, and `mmx-violations=0`. → a reader sees a stale image: registers silently revert to an older value. `target/i386/tcg/translate.c`.
- **MMX entry runs once per TB** (both modes): `gen_enter_mmx` emits the x87 flush, the stale-double test (`helper_enter_mmx_sync` only if a byte is set, see the doubles rule), fpstt = 0 (a store to env->fpstt in deferring blocks (`x87_defer`), which leave the `fpstt` global unused; the global elsewhere), `x87_top` = 0 and the tag store only in a TB's first MMX insn, then skips them while `mmx_entered` holds; no flush can store a double before the next full entry. Every insn that can move fpstt, change the tags or leave x87 results pending clears it (`gen_x87`, all of 0xd8-0xdf; EMMS/FEMMS; FXRSTOR; XRSTOR), and a new one must too. fpstt moves only after that flush, which froze word 2. Refute with `XEMU_X87_REFUTE=1` (`mmx-violations=0`, checked at every MMX insn). → MMX code reads stale x87 images, or runs with an older TOP or tags. `target/i386/tcg/translate.c`.
- **The x87 conversions' rare cases run past the TB's last instruction** (both modes): ld80f/st80f emit their cold cases (±0, subnormals, inf/NaN, and any ld80f input outside the in-range path) as `out_stub` labels beside the qemu_ld/st slow paths (`tcg_out_ldst_finalize`). No restore data covers them, so a stub may not fault or call C (only `tcg_x87_ld80_slow`); it takes TMP0-TMP2 as the branch left them and returns with a B. → a host fault or a `cpu_restore_state` miss inside a stub. `tcg/aarch64/tcg-target.c.inc`.
- **x86_64 hosts run the hot x87 ops on the host x87 unit** (both modes; `g_x87_hw`): the tcg/i386 `x87_*` ops stay bit for bit the x86_64 `__hard` helpers in `fpu_helper.c` (same instructions, same control word: change both). The vCPU thread's host x87 control word holds the guest's PC and RC (`xemu_sync_host_x87_cw`: `update_fp_status` on the vCPU thread, `x86_cpu_exec_enter`, and after every longjmp in `cpu_exec_longjmp_cleanup`, because Win64's and Darwin's x86_64 longjmp restore the control word `sigsetjmp` saved), so libm in a helper goes through `XEMU_LIBM` (`0x37f`) and device code on the vCPU thread through `xbox_host_fp_enter` (`0x37f`/`0x1f80`). With a static TOP their m32fp/m64fp/m32int/m64int forms run on the guest page (`x87_*_g`, guest accesses like qemu_ld/st: a new pass over guest accesses counts them too); the slow path runs the same insns through `(%rsp)`. `X87_NO_WG` helpers (`TCG_CALL_NO_WG` on x86_64) write no TCG global: one that moves fpstt or writes CC_* drops the flag. Only the Windows goldens (docs/windows-gating-audit.md §V) and CI's hard-FPU Roswell leg (`roswell-hard-fpu` in ci.yml, filter `.github/roswell/windows_roswell_hardfpu.json`; `continue-on-error` until its first green run) check this path; an x86_64 macOS build under Rosetta 2 reproduces the Windows debug-build hashes. → x87 results that differ from the helpers', or guest math at another precision or rounding. `tcg/i386/tcg-target.c.inc`, `target/i386/tcg/fpu_helper.c`.
- **Device I/O happens only from a TB's last insn, and TBs keep no `can_do_io`** (icount without replay; only replay emits the stores): `io_prepare` asks `xemu_io_ra_in_last_insn(retaddr)` and sends a mid-TB access through `cpu_io_recompile`. Its answer is cached per host code address until `tb_flush`, so code that rewrites run TB code without a flush must also bump `tb_flush_count`. The flag stays true, so the "Bad icount read" and "Raised interrupt while not in I/O function" guards are dead: a helper that reads `QEMU_CLOCK_VIRTUAL` from TB code must end its TB (`translator_io_start`). Code that must tell an access's first pass from its `cpu_io_recompile` rerun asks `xemu_io_ok(cpu, ra)`, never the flag (the `xemu-watch` log does); `cpu_watchpoint_hit_reruns` takes ra 0 as an interrupt delivery in both modes. → clock reads that depend on TB shape, so runs diverge after loads; a stale answer skips a recompile. `accel/tcg/translate-all.c`.
- **TB code keeps EAX..EDI in x8-x15 and EIP/CC_DST/CC_SRC/CC_OP in x24-x27, not in env** (both modes, aarch64 hosts; `tcg_pin_env_global`, registered by `tcg_x86_pin_globals` before the prologue). env holds them only at the prologue/epilogue, around qemu_ld/st slow-path helpers (after the sub-page prefilter) and around helper calls: the GPRs at every call, EIP/CC_* only for helpers that may read globals (stored before) or write them (reloaded after). So C code may touch these fields only from such a sync point: a helper marked `TCG_CALL_NO_RW_PINNED` may not read, write, fault or `cpu_loop_exit`, a `TCG_CALL_NO_RWG` one must stay pure, and TCG code never loads or stores those env offsets directly. Check with a `--debug` build over the goldens: it poisons the env homes (0xdeadbeef) while TB code owns them and aborts on a lost write ("a helper without a reload wrote the pinned env field"). → exception frames push a stale ESP/EFLAGS, `cpu_restore_state` rebuilds EIP from a stale page (CF_PCREL), or a register write is lost. `tcg/tcg.c`, `tcg/aarch64/tcg-target.c.inc`.
- **TB code reuses softmmu TLB walks within straight-line code** (both modes, aarch64 and x86_64 hosts; `tcg_tlbm_plan` in `tcg/tcg-tlbm.c.inc`, which tcg.c includes, so aarch64 keeps its static names and PGO profile). aarch64 reserves x4-x7: the load slot holds {ntag = -page, addend} in x4/x5, the store slot {ntag, &CPUTLBEntry} in x6/x7. x86_64 reserves R8-R11: the load slot in R10/R11, the store slot in R8/R9, all call-clobbered on SysV and Win64 (never call-saved: the pinned-layouts row). A slot is used only between its walk and the next label, helper call or TB exit, and slow paths reset it after their helper call (`tlbm_out_invalidate`: ntag = 1 << 32, and x7 = env in normal mode; x86_64: ntag = 0x80000000, its shared store checks the bound before it reads through R9). So the vCPU's own C code may change `addr_read` or an addend only behind a call or a slow path. In normal mode shared stores re-read `addr_write`, so other threads may keep re-arming TLB_NOTDIRTY (`tlb_reset_dirty`), but an addend change from another thread would break the load slot. Under icount (`tlbm_st_addend`) the store slot holds the addend too and reads no `addr_write`, so a re-arm must not land while TB code runs: a new off-vCPU caller of `physical_memory_dirty_bits_cleared` (any test-and-clear or snapshot of a dirty bitmap) under icount runs with the VM stopped or while the vCPU waits in `pfifo_icount_sync`, or calls `memory_global_after_dirty_log_sync()` before it reads the pages (audit: docs/optimizations.md, TLB memo entry). A TB-side path back from a walk that missed without `tlbm_out_invalidate` ends the store slot itself (the sub-page prefilter's inline store does). A backend stub that calls C outside a slow path must reset the slots or leave the slot registers alone (`tcg_x87_ld80_slow` touches none of them). Aligned accesses share (the check rotates the page offset right by the alignment bits, so a misaligned address fails the bound), and a shared access's slow-path re-walk must check the alignment too, or a misaligned `movaps` would skip its #GP; every op that calls `prepare_host_addr` with the memo on (qemu_ld/st, qemu_ld2/st2, `qemu_ld_v128`, `qemu_ld_fp`/`qemu_st_fp`, x86_64's `x87_*_g`) is counted by the planner in the same order, and sets `memo_access` to where the re-walk returns. Helper arguments may use the slot registers (`tlbm_call_regs`: x4-x7, and R8/R9 are argument registers on both x86_64 ABIs). Rosetta 2 advertises AVX only under `ROSETTA_ADVERTISE_AVX=1`, and without AVX 16-byte SSE accesses are helper calls, so on the Mac x86_64's qemu_ld2/st2 and aligned shares run only with it: set it on the debug runs too, and on both arms of an A/B or neither (it moves the det Minsns base ~4%). Check with a `--debug` build over the goldens: it walks the TLB behind every shared access and aborts ("the TLB entry changed under a TLB memo"); for stores it masks TLB_NOTDIRTY out of the live entry and checks the `addr_write` the share check read instead (icount: the live entry must still be the bare page, TLB_NOTDIRTY allowed only while a migration runs). The goldens run icount, so normal mode's re-reading stores meet real off-thread re-arms only in a normal-mode debug run (offscreen Vulkan after a loadvm, renderer asserts on: heavy-f1, stream-e2 and heavy-w2 loads run clean). → loads through a stale addend, or a lost dirty mark (stale nv2a upload). `tcg/tcg-tlbm.c.inc`, `tcg/aarch64/tcg-target.c.inc`, `tcg/i386/tcg-target.c.inc`.
- **TB code is split hot/cold** (both modes, aarch64 hosts; `TCG_TARGET_COLD_CODE`): a region is cut into 1 MiB chunks (a tail of at least 256 KiB makes one more, shorter one), each a hot first quarter that holds TB bodies back to back (`tb->tc`) and a cold rest that holds, per TB, its TranslationBlock, its qemu_ld/st slow paths, x87 stubs and constant pool (`tb->xemu_cold`), then its search data. Both parts of a TB sit in one chunk, so a reference between them may span up to 1 MiB: B.cond, CBZ/CBNZ, ADR, LDR (literal) and the goto_tb LDR of `jmp_target_addr` reach that far, a TBZ/TBNZ (±32 KiB) does not and must never cross, and a stub goes back with a B. Code emitted at `tcg_out_ldst_finalize`/`tcg_out_pool_finalize` time lands in the cold part, which `tcg_tb_lookup` and `cpu_restore_state` don't see: a stub may not fault or be the return address a helper unwinds from (slow paths pass the hot `raddr`), and anything that maps sampled host PCs to TBs also searches `xemu_cold` (`XEMU_GUEST_PROF` does). Every write into a part checks that part's highwater, as the body does per op; a TB that runs past one starts over in the next chunk (`tcg_code_overflow`), so no single emission may exceed `TCG_HIGHWATER` (1 KiB): a body op that does has written over the cold part and aborts (`tcg_gen_code`'s g_assert), a stub runs into the next chunk. The recycler reuses both parts as they are; `tb_flush` rewinds every cursor (`tcg_region_assign`). Keep warm stubs (ld80d's image path, the memo re-walk, the store prefilter) cold too: beside the body they cost more than the excursions they save. → a reloc that can't reach (the TB is halved over and over), that g_assert, or a stub with no TB to unwind to. `tcg/region.c`, `tcg/tcg.c`.
- **Liveness pass 1 visits only the temps in its sets** (both modes; `LivenessSets`): block ends, conditional branches, global syncs and calls update only the temps in `live`, `nomem`, `stale` and `tb`, and take every other temp to be as `la_func_end` leaves it. Code in `liveness_pass_1` that makes a temp live or dead, or copies a preference into a dead temp, calls `la_note_live` / `la_note_dead` or sets its `stale` bit. Liveness pass 0 runs inside `reachable_code_pass`, so no pass may add or move ops between it and pass 1. → wrong liveness with no assert in a release build: a global not stored back, a live register reused. `tcg/tcg.c`.
- **Find a divergence** with a per-frame RAM hash (`xemu-frame-advance 1` + `pmemsave`), then a temporary MMIO/PIO trace diff (`memory_region_dispatch_read/write`); the first differing read names the device.

### Threads, locks, clocks
- `QEMU_CLOCK_REALTIME` is `CLOCK_MONOTONIC`; `QEMU_CLOCK_HOST` is wall time and can jump. Pace and throttle on REALTIME. The macOS main loop never busy-waits: sub-ms timer precision comes from a one-shot kqueue `NOTE_CRITICAL` timer in the poll set plus a 25 µs final spin (`qemu_poll_ns`). `util/qemu-timer.c`.
- Under `-icount sleep=off` (and `sleep=on` with `XEMU_ICOUNT_LIVE_PADS=1`, which first waits for real time: `icount_paced_wait_ns`) only the vCPU thread warps `QEMU_CLOCK_VIRTUAL`, between slices, by exactly the time to the next timer; stock `sleep=on` warps by elapsed real time and is not reproducible. Off the vCPU the virtual clock lags by the running slice's uncounted instructions (HLT reads as idle before `icount_process_data`), so no other thread may warp it or arm a VIRTUAL timer relative to now. → identical runs rarely diverge. `accel/tcg/icount-common.c`.
- Never block while holding the BQL. `surface_access_callback` drops it before taking `pgraph.lock`. → the whole VM freezes.
- Every `pfifo_kick(d)` caller holds `d->pfifo.lock` across the kick-set and the broadcast (the idle wait is an untimed `qemu_cond_wait`). `pfifo_run_puller` drops `pfifo.lock` to take `pgraph.lock`, so don't hoist checks that assume it's held (except the deterministic inline run, which holds both throughout: `pfifo.inline_locked`; method code that takes the BQL goes through `pgraph_inline_bql_lock`). Never suppress a kick. Normal mode's DMA_PUT doorbell skips the lock (`pfifo_put_doorbell`): a release store of PUT, then a Dekker pair with the thread, which clears `doorbell` before the pusher's acquire load of PUT and rechecks it after setting `parked`; keep both halves. One exception: inside a flip stall (`waiting_for_flip`, read with acquire against FLIP_STALL's release store, and READ_3D == WRITE_3D) a doorbell whose PUT differs from GET publishes PUT and the flag but wakes nobody, since the thread could only stall again (a PUT equal to GET still wakes: FIFO-idle report delivery needs the iteration); only the vCPU ends a flip stall (NV_PGRAPH_INCREMENT kicks; a direct NV_PGRAPH_SURFACE write is its own store, which the doorbell's test reads), so a new way to end one from another thread must kick (`XEMU_PFIFO_STALL_DOORBELL=0` always wakes). → permanent PFIFO hang. `nv2a/pfifo.c`.
- **The threaded pusher may be far behind the guest, so a ring restart freezes the unread tail** (normal mode; `pfifo_freeze_unread`, `pfifo_frozen.h`). It reads each pushbuffer word from guest RAM only when it executes it, and blocks on host GPU fences (a finish waits for the previous flight) and on guest DPC round trips (NOP notifies), where the hardware's DMA engine would have fetched up to 256 words into CACHE1 already. pbkit's `pb_reset()` writes a jump at PUT, moves PUT to the ring head and waits only 100 ticks for DMA_GET before it writes the next frame anyway. So a DMA_PUT write that moves PUT back behind DMA_GET copies the words from DMA_GET through the old PUT's (the jump back) before PUT is published (a PUT moved back to or past GET freezes nothing: the pusher won't run those words, and a reset that writes GET first rewrites them), and the pusher reads them from the copy (after its RAM read, behind a read barrier: no freeze seen means the word was read before the guest could change it) until a jump, call or return, or it passes the copy. One copy at a time; a guest write of DMA_GET (USER or PFIFO) or of PFIFO's DMA_PUT, reset and loads drop it. Normal mode only (`ring_freeze`): icount's pusher runs at every guest write. A new pushbuffer reader in the threaded pusher goes through `pfifo_frozen_lookup`; a new DMA_PUT writer calls `pfifo_freeze_unread` first. `XEMU_PFIFO_RING_FREEZE=0` turns it off. → data words run as commands after a lag: "Reserved pb command" aborts, bogus jumps, a wedged FIFO (Roswell FpuTestXiso on the macOS CI runner). Reproduce locally by delaying the NOP notify in `pgraph_NV097_NO_OPERATION_handler` (30 ms aborts most of the xemu-test suite with the freeze off). `nv2a/pfifo.c`, `nv2a/user.c`.
- **The deterministic pusher runs inline, under both locks, on the thread that needs PFIFO at rest** (icount, null and Vulkan renderers; GL's contexts belong to the PFIFO thread, which keeps its pusher): the vCPU after each guest PFIFO, USER or PGRAPH write and at the icount sync hook, and the main loop in `nv2a_vm_state_change` at a pause or before a load (`pgraph_request_report_delivery`, then `pfifo_icount_sync`), where the pusher is already at rest, so that run only waits for the delivery. With Vulkan the PFIFO thread stays for the other threads' requests (present and screendump syncs, surface downloads, report deliveries: `pgraph_vk_process_pending`, under `pgraph.lock`), so renderer state has three threads, serialized by `pgraph.lock`. Every sync first waits until the thread has acted on every kick so far (`idle_seq == kick_seq`; otherwise a pause wouldn't wait for the delivery it asked for; `kick_seq` starts at 1, so the first sync also waits out renderer init and the mode it reads next is final), and every inline run ends with the drain the thread did before it parked (`pgraph_process_pending_reports`); the thread does no drain of its own then, since one under `pfifo.lock` alone could land while a run has dropped both locks for the BQL. A run entered with the BQL (the sync hook, PFIFO MMIO, the main loop) keeps it across fence waits: nothing a run reaches may wait for a thread that wants the BQL, `pfifo.lock` or `pgraph.lock` (the PFIFO thread above all: no `pfifo_kick` plus event wait in method code), and a report trap inside a run delivers in place (`pfifo_in_inline_run`, thread-local, since other threads read `inline_locked`): `det_reports_await` would wait for a thread that needs the run's locks. That branch is a guard no run has taken (the pusher touches guest RAM by pointer, past the traps; none in the anchors, the cold boot or pack 05's d2). → a deadlock, or reports or requests that land mid-run, so RAM differs between runs. `nv2a/pfifo.c`, V`reports.c`.
- **The deterministic inline pusher assumes it runs alone** (`pfifo_run_pusher_impl(d, true)`; the threaded copy keeps every check). It keeps DMA_GET in a register, reads DMA_PUT once, checks FIFO access and `waiting_for_nop` only at the loop top, and runs a kelvin command's data words in one fused loop (`pfifo_inline_command`, entered straight from the header): PULL0, the engine binding and the graphics class are checked once per subchannel per run (`fused_subch`, dropped whenever the per-word path runs a method), the CTX_CACHE → CTX_SWITCH copy runs only when the subchannel changes (`pg->ctx_switch_subch`, reset at every run start), each handler call is followed only by a test of `waiting_for_nop`, `waiting_for_flip` and `waiting_for_context_switch`, and DMA_GET, DMA_STATE, DCOUNT, DATA_SHADOW and LOW_MARK are written back at the command's end or stall, as the per-word path leaves them. Only guest MMIO, loads, reset, method 0 and the header decode write that state, and none lands mid-command; method 0, object methods (0x180-0x1ff, RAMHT lookups), a method range that would wrap and non-kelvin classes take the per-word path. Word counts follow the per-word path's wrapping `(put - get) / 4`: GET past PUT is normal (the ring jumps back). A handler that writes a PFIFO register, FIFO access or a CTX register, or sets a new stall flag, must end the fused loop (join its flag test) and reset `fused_subch` and `ctx_switch_subch`. → a stale graphics class or DMA_GET, or a stall that leaves other registers than the per-word path; the det goldens diverge. `nv2a/pfifo.c`, `pgraph/pgraph.c`.
- `cpu->mem_access_callbacks` is an RCU list (entries freed after a grace period). Any thread doing guest DMA walks it and must be `rcu_register_thread()`-ed (qemu_main is, in `ui/xemu.c`). A callback change refills only the TLB entries for its pages (`tlb_flush_host_range`, inside the insert/remove safe work), so nothing flushes the TLB in a steady scene and it is floored at 8192 entries in both modes. → SIGSEGV in `flatview_read_continue`; a trap that misses its first access. `system/physmem.c`.
- Anything that makes a main TLB entry writable-clean (a fill, a victim swap, `tlb_set_dirty` clearing `TLB_NOTDIRTY`) sets its `wclean` bits under `tlb_c.lock` (`tlb_wclean_note`): `tlb_reset_dirty` visits only set bits. → a page the renderer, VGA or code tracking watches stops trapping writes (stale textures or vertices, missed SMC). `XEMU_TLB_WCLEAN_REFUTE=1` must report `misses=0 unset=0`. `accel/tcg/cputlb.c`.
- Guest RAM is also written by plain host stores that skip qemu_ld/st: i386 REP MOVS/STOS runs of 1-31 elements after an inline copy of the fast path's TLB compare (`gen_rep_short`), and longer runs after `xemu_probe_ram` (`helper_xemu_rep_bulk`). Anything that must see each guest access (dirty tracking, SMC, watchpoints, MemAccessCallbacks, MMIO) keeps a flag in the TLB comparator, as all of them do now; a hook only in the qemu_ld/st fast path or in `gen_ldst_prologue` misses these. → missed dirty, SMC or trap events. `target/i386/tcg/translate.c`.
- **`tlb_set_dirty` clears TLB_NOTDIRTY only on entries for the page the store dirtied** (equal `xlat_section`). Another mmu_idx may map the same virtual page elsewhere: x86's `MMU_PHYS_IDX`, through which the page walker probes a PTE's page once and then sets A/D with a cmpxchg on the host pointer. → the walker's PTE writes skip the dirty log (migration and incremental checkpoint restores lose pages) and code on that page keeps stale TBs. `accel/tcg/cputlb.c`.
- **Every guest RAM write reaches the migration dirty log while it runs** (migration; incremental checkpoint restores and saves against a base, `ui/xemu-checkpoint-ram.c`). TCG stores trap on TLB_NOTDIRTY and DMA marks through the address space; a device store straight into RAM calls `memory_region_set_client_dirty` (with `DIRTY_MEMORY_MIGRATION` alone if it marks nothing else) under `global_dirty_tracking`: APU voice and notifier stores, nv2a semaphores and reports, surface write-backs. Blocks up to 4 MiB (BIOS, MCPX shadow, nv2a RAMIN) are compared whole. → a restore or base save misses pages; check with `verify` (`pages-missed` 0).
- **Large transient buffers come from mmap, not the heap**: macOS keeps every freed large malloc block resident (`malloc_zone_pressure_relief` frees nothing), so loadvm/savevm whole-state buffers and checkpoint pages and device states use `qemu_anon_ram_alloc`/`qemu_anon_ram_free`; a QIOChannelBuffer handed such a buffer must get it back before its close `g_free`s it and must never grow (`whole_buf_*`). The Xbox never maps the PC machine's 128 MiB `pc.ram`; `RAMBlock.xemu_zero` makes loads, saves and checkpoints take it as zero pages without reading it (on macOS a read faults a page in). → every load, save or deleted checkpoint leaves 7-90 MiB in the footprint for good; a load faults in all of pc.ram. `migration/savevm.c`, `migration/ram.c`, `hw/xbox/xbox.c`.
- **TLB_WATCHPOINT pages take the softmmu slow path**: that covers gdb `Z2`-`Z4`, MemAccessCallbacks and the QMP access log (`xemu_watch_check`, next to every `mem_check_access_callback_vaddr`). A fast path that touches guest RAM without those helpers declines such pages, as `xemu_probe_ram` and the sub-page store prefilter do. The log only records (no state restore, no `cpu_loop_exit`, no invalidation); a write hit kicks the vCPU once (`async_run_on_cpu`) so a work item reads the stored bytes back at the next block boundary, unless the next hit does first. Its slow-path calls are out of line (those callers keep their PGO profile); the refill check is one inlined atomic load and branch, which changes `tlb_set_page_full`'s profile hash until the next retrain. A gdb watchpoint hit in translated code reruns its insn alone with `cpu->watchpoint_hit` set, and the log skips the accesses the rerun repeats; a hit in an interrupt or exception delivery has no rerun (`cpu_watchpoint_hit_reruns`) and stops after the delivery. The resume after a debug stop drops what is left of a hit (`watchpoint_hit`, a pending `CPU_INTERRUPT_DEBUG`; `gdbstub/xemu-gdb.c`). Code in a load/store helper that writes a TB brackets the write with `qemu_thread_jit_write/execute` (`tb_phys_invalidate`). → missed or wrong log hits; a wedged vCPU at the first watchpoint hit. `accel/tcg/xemu-watch.c`, `accel/tcg/cputlb.c`.
- Code patched between `flush_idcache_defer_begin` and `_end` (the xpage backstop's unlink walk; a new TB's body and cold part in `tcg_gen_code`) is not icache-coherent until `_end`, which runs one DSB / IC IVAU / DSB / ISB sequence for the batch (with a DSB every 20 IC IVAUs, as libsystem does on M1-M4). No TB may run inside the window, on any thread; the queue is per thread and windows don't nest (`flush_idcache_defer_begin` asserts). → a severed chain still jumps to its old target. Only link patches may be seen stale: a B to another TB replacing a slot's reset B (aarch64 `tb_target_set_jmp_target`, from `tb_add_jump`) waits in the thread's link queue (`flush_idcache_link`), since B to B is a permitted concurrent modification and the old B exits to the dispatcher. The queue drains when 64 are queued, when `tb_add_jump` finds the slot already linked to the TB it would link (a stale fetch), at every `cpu_exec` return and before `tb_flush` reuses the buffer. Resets (unlinks), LDR-form links and new code flush before any TB runs. A fresh TB's slots get no reset patch: aarch64 emits goto_tb as B +8, the reset form, inside `tcg_gen_code`'s window (`TCG_TARGET_GOTO_TB_EMITS_RESET`; recycled TBs still take `tb_reset_jump`), so `tcg_out_goto_tb` and the reset encoding in `tb_target_set_jmp_target` change together. → a new patch class in the link queue needs that exit-and-drain argument; an unlink left there keeps a chain into a dead TB. `util/cacheflush.c`, `accel/tcg/tb-maint.c`, `accel/tcg/cpu-exec.c`.
- **TCG W^X (Apple, both modes): the vCPU thread is in execute mode outside write brackets that close themselves**, and `cpu_tb_exec` no longer flips it per TB entry. The brackets: `tb_gen_code` (a fault that leaves translation by longjmp is closed in `cpu_exec_longjmp_cleanup`), `tb_add_jump`, the tb-maint invalidate/unlink/revalidate paths (`tb_phys_invalidate` included, which a watchpoint hit reaches from a helper) and the DSP JIT (the det APU tick on the vCPU thread relies on those, with no flip of its own); `cpu_exec` keeps one flip per slice only as a safety net for the thread's first slice and code outside `cpu_exec`. TBs live in the code buffer, so a new write to a TB field (its `jmp_lock` included) or to code takes its own `qemu_thread_jit_write()` … `qemu_thread_jit_execute()` pair in one function, with no guest or DSP JIT code run inside it; no TLS-cached state. → the guest freezes with no crash report: the vCPU spins at 100% in a fault loop at a code-buffer address (`sample` shows `???` at 0x3000… under `cpu_exec_loop`). `accel/tcg/cpu-exec.c`, `accel/tcg/translate-all.c`.
- Guest loads carry no load-load barrier in normal mode, and no guest access carries any barrier under icount, until a network backend attaches: `xemu_net_enable` calls `xemu_guest_mo_keep_all` (every barrier, both modes, TBs flushed as vCPU safe work). A device thread that orders data before a flag the guest polls in RAM (`pci_dma_write` rings like nvnet RX; PFIFO data a later semaphore release publishes) needs the reader's load-load barrier: deliver by interrupt, a locked or load-acquire MMIO read (USER DMA_GET), or call `xemu_guest_mo_keep_all`. Left open: a title that spins on a semaphore with loads alone, then loads PFIFO-written data with no store between. Normal-mode stores keep their barrier because OHCI walks guest-linked descriptors. → the guest reads stale data. `tcg/tcg-op-ldst.c`.
- PFIFO, vblank, the vCPU (normal mode: `mttcg_cpu_thread_fn`, `XEMU_VCPU_QOS=0` opts out; det mode: the RR thread), the main loop (`qemu_main`; `XEMU_VCPU_QOS=0` opts out in normal mode), the APU frame thread, and any new frame-critical thread run at `QOS_CLASS_USER_INTERACTIVE` on macOS. On Windows the normal-mode vCPU (`mttcg_cpu_thread_fn`), PFIFO and APU frame threads run at `THREAD_PRIORITY_ABOVE_NORMAL` (`XEMU_VCPU_QOS=0` leaves all three at normal); the det RR thread, the main loop and vblank stay at normal. At default QoS the busy-polling vCPU's priority decays below the threads it feeds, and under host load it loses part of its core; a default-QoS thread holding a lock the vCPU takes (the APU's `d->lock` in `vp_write`) gets preempted inside it. → jitter that looks like a regression.
- **A QoS request applies only in a process with an app role**: one spawned from an app (Terminal, an agent's app) inherits the app type but no role, and xnu squashes a roleless app's USER_INTERACTIVE/USER_INITIATED threads to legacy priority 31, while pthread still reports the class asked for. AppKit's check-in gets windowed and offscreen xemu a role from RunningBoard (offscreen UI, an unfocused window UI non-focal); null mode starts no Cocoa app and sets UI itself (`xemu_os_set_app_role`, `setpriority(PRIO_DARWIN_ROLE, 0, PRIO_DARWIN_ROLE_UI)`). A new Cocoa-free launch path does the same. A launchd job (daemon type) can't take a role (ENOTSUP); its ProcessType caps its QoS. Check: base priority 46 in `proc_pidinfo(PROC_PIDTHREADINFO)`, CPU billed to `ri_cpu_time_qos_user_interactive` rather than `_legacy`, and runnable ≈ CPU seconds in bench-det. → the null vCPU waits for a core most of the time on a loaded host (3-4x wall at load 70-96), partly on E-cores. `ui/xemu-os-utils-macos.m`.
- **The normal-mode vCPU halts in KiIdleLoop** (`helper_xemu_ki_idle`, reached from `gen_STI`'s idle match in both modes): with no DPC queued, no NextThread and nothing pending, it spins 50 µs of host time per idle span (`env->xemu_idle_t0`/`_last`; calls under 5 µs apart are one span), then halts as HLT does and sleeps on `halt_cond` until `cpu_interrupt` kicks it; icount halts at once. The loop reads only the DPC list and NextThread, which only interrupt handlers change, so work for an idle guest must arrive as an interrupt (raised with the BQL held), never as state the vCPU is expected to notice by spinning. `XEMU_KI_IDLE_HALT=0` keeps the spin. → the guest sleeps through the work until the next interrupt (the PIT ticks at 1 kHz). `target/i386/tcg/system/misc_helper.c`.
- **The normal-mode vCPU polls a contended BQL for up to 10 µs before it sleeps** (`bql_lock_impl` → `bql_lock_spin`; `bql_spin_enable_self` turns it on for the MTTCG thread only, so icount never spins): a trylock every 200 ns, paced on `cntvct_el0` because macOS's `CLOCK_MONOTONIC` counts whole microseconds. macOS mutexes are first-fit, so the spinning vCPU takes the BQL ahead of threads asleep on it (the main loop's contended waits triple, each shorter). The halt wait re-takes the BQL inside `qemu_cond_wait` and still sleeps. `XEMU_BQL_SPIN=0` keeps the plain lock. Keep the spin on the vCPU: → on a thread that waits behind the vCPU or holds the BQL long it burns a core and starves the holders. `system/cpus.c`.
- The jump cache is 2048 two-way sets (`tb_jmp_cache_way0`; way 1 is the next entry, in the same page range): a fill moves way 0 to way 1, a C way-1 hit swaps the two, and the inline probe reads way 0 only. Code that indexes `jc->array` handles both ways (`tb_jmp_cache_inval_tb`). → a lookup misses its own entry. `accel/tcg/cpu-exec.c`, `accel/tcg/xemu-inline-jc.c`.
- **The near-return memo jumps without reading the TB** (i386 `env->xemu_retc`): the inline probe (`xemu_gen_inline_ret_memo`, emitted only in TBs with `cpu->tcg_cflags`) compares eip and flags as one word and the cs_base key, then branches to the entry's `tc_ptr`, which the fill sets only for a TB with the base cflags. No `CF_INVALID` check: every i386 TB is `CF_PCREL`, whose invalidation clears the whole memo (`tb_jmp_cache_inval_tb`; a load's deferred invalidations rely on its `tlb_flush` running before the vCPU does), and the fill re-reads the TB's cflags behind `smp_mb()` for an invalidation from another thread between its lookup and its stores. A non-PCREL i386 TB or a new way to drop a TB or remap code must clear the memo (`xemu_i386_ras_flush`, `_flush_page`); the probe and the C side share `xemu_retc_index`. A `--debug` build checks the TB behind every inline hit ("a lost invalidation"). → a ret jumps into dead or stale code. `target/i386/tcg/xemu_ras_helper.c`.
- The x87 control word changes only through `cpu_set_fpuc()`, because PC and RC are baked into `tb->flags`, and `cpu_set_fpuc()` changes no other `hflags` bit: fldcw leaves its TB through the jump-cache probe, which takes RC/PC from `env->hflags` and every other flag bit from the TB's own flags (`gen_eob`). One exception: in write-through blocks a word that keeps RC and PC bit 9 is stored inline with the softfloat precision, and the TB chains on (`gen_fldcw_wt`), so state that `update_fp_status` derives from other fpuc bits must be stored there too. → the write-through x87 path runs at a stale precision; the probe enters a TB built for other flags; softfloat helpers round at the old precision.
- **A fatal error must end the process, never trap in place**: `qemu_thread_create` keeps SIGTRAP and SIGBUS deliverable on macOS, and fatal paths call `abort()` or `_exit()`, never `__builtin_trap()` (`VK_CHECK` and the fence waits end in `pgraph_vk_fatal_error`: headless exits 1 after a fixed line, windowed aborts). macOS does not force a synchronous signal through a blocked mask, so the thread re-executes the trap forever at full CPU, still holding its locks, and SIGTERM's shutdown request never runs. → a crash that looks like a hang (AZ-293: PFIFO on `pgraph_vk_finish`'s `brk`, the vCPU waiting for `pgraph.lock`). `util/qemu-thread-posix.c`, V`debug.h`.
- **A unix listener never takes a live process's path** (upstream deviation, keep it across merges): `unix_listen_saddr` probes the path before its unlink with a datagram `connect()` (`EPROTOTYPE` or success = something is bound there; it queues nothing on the listener and still sees a busy one, where a stream probe is refused on macOS) and fails with `EADDRINUSE`; only a stale socket (`ECONNREFUSED`) or a non-socket is replaced. A `QIOChannelSocket` listener records its socket file's `st_dev`/`st_ino` at listen and its close unlinks the path only while `lstat` still matches (nothing recorded: never). POSIX only; Windows keeps upstream's unlink. → a second launch with the same `-qmp unix:` path orphans a running xemu's control socket. `util/qemu-sockets.c`, `io/channel-socket.c`.
- **Shared guest RAM never takes a live holder's name** (`XEMU_RAM_SHM` or `[automation] ram_shm`): the creator flocks `/tmp/xemu-shm-<uid>/<name>.lock` before its `O_EXCL` create and holds it for life; a lock file is unlinked only while locked, so a taker re-checks after locking that the path is still its inode. A free lock means stale unless the bytes still change (a running pre-lock build; a paused one looks stale and is replaced, and a pre-lock exit unlinks the name whoever holds it); exit unlinks the name only while it is still ours (inode on Linux; same bytes on macOS, which gives shm no inode). The `[automation]` table applies only to the pref dir's config with no `-config_path`, `XEMU_BASE_PATH`, portable mode or marker (`xemu_settings_why_not_pref_dir`, `ui/xemu-automation.c`), and its endpoints are skipped, never `error_fatal`. → an agent's xemu takes or unlinks the player's tracker name or port, or a Dock launch dies on a taken port with no message. `hw/xbox/xbox.c`.
- **A QMP command that waits for vblanks ends on every VM stop it didn't make** (`frame_advance_vm_state_change`): `xemu-frame-advance`, `xemu-run-until` and `xemu-run` hold the QMP dispatcher while they wait, and vblanks come only while the VM runs (under icount no timer fires while it is stopped). A save-vm/restore-vm stop is waited out until the code that made it has returned (`frame_saveload_check_bh`, an iohandler BH), then ends the advance if the VM still isn't running: upstream's HMP `loadvm` and `snapshot-load` resume only on success, so a failed load stays in restore-vm. The gdbstub stops a running VM as paused on attach, on ^C and on any byte it receives; vm_shutdown's stop (SIGTERM) must end it too, since `monitor_cleanup` waits for the dispatcher. → the command never returns, new QMP connections get no greeting (they sit in the listen backlog behind the held client, whose close goes unnoticed) or ECONNREFUSED, at 0% CPU, and SIGTERM never exits. `ui/xemu.c`.

### Savestates
- **A snapshot's xemu data stays version 1; new fields go in tagged records after the thumbnail, inside its size** (`XEMU_SNAPSHOT_DISC_FP_TAG`). Older and upstream xemu read the v1 fields and ignore the rest, and every load skips the blob by its size. A version bump makes older readers drop the disc path as well, and their menu load then ejects the tray's disc. A menu load skips the disc dialog only on content (`xemu_disc_same_content`: the saved fingerprint, or an older snapshot's saved file unchanged since the save), never on path, size or XISO directory tables, since two builds can differ in one level file rewritten in place. → older builds lose the disc path and thumbnail of new snapshots; a state runs on a disc it wasn't saved with. `ui/xemu-snapshots.c`, `ui/xemu-disc-fingerprint.c`.

## Glossary (fork-specific)
- **flip**: guest `FLIP_STALL`; flips/s = guest fps (cap 60). **finish**: `pgraph_vk_finish(reason)` = submit + wait on the previous slot's fence.
- **zeta shape switch**: Azurik flips one depth allocation between 1280×480 and 256×256 swizzled every frame.
- **zpass report**: occlusion query delivered at flip or slot reclaim; plain submit after 300 µs of FIFO idle (`REPORTS_IDLE_BUDGET_NS`). Under icount, delivered lazily (see Deterministic reports).
- **EP** DSP runs at 1/8 of GP's rate, enters blocks mid-way and stores data into P-space next to its code (no overlays). **hard_fpu**: x87 math in double precision (`hard_fpu=false` for exact). **Anchors**: `azurik-heavy-f1`, `-w2`, F5, listed in `../fixtures/README.md`.

## Analysis recipes
1. **Budget**: sum all nsprof counters against measured frame time; if short, instrument more before ranking causes.
2. **CPU- or GPU-bound**: remove a wait class structurally. If total wait and fps stay flat, it is GPU time; confirm with a second, structurally different attempt at the same draws/flip.
3. **Bisect**: list the full good-vs-bad delta (launch path!), reproduce the failure first, flip one variable per fresh launch, run the all-but-X control, and score frames with an automated oracle.
4. **Driver crash survives a structural fix**: read the pinned MoltenVK version's source; fix by construction.
5. **Pool cadence changes**: worst-case demand vs per-slot capacity; add a runtime guard with its own finish reason; prove it fires by shrinking the pool (`XEMU_MAX_QUERIES=64` shrinks the query pool only; the report pool has no knob).
